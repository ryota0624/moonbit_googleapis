# 完了報告: Cloud Storage e2e テスト実装

## 実装内容
- `e2e/storage` パッケージを追加し、fake-gcs-server を使った Storage e2e テストを実装。
- Firestore e2e と同じ `NoAuthHttpClient` パターンを採用し、Authorization ヘッダーを除去してエミュレーターへ接続。
- 以下 2 シナリオを実装:
  - バケットライフサイクル: `buckets_insert` → `buckets_get` → `buckets_list` → `buckets_delete`
  - バケット prefix 一覧: 2 バケット作成 → `buckets_list(prefix=...)` で両方の存在確認 → 2 バケット削除

## 技術的な決定事項
- エミュレーターは `fsouza/fake-gcs-server:latest` を採用。
  - 理由: `/storage/v1/b` を含む GCS 互換 REST エンドポイントを提供し、生成済み `StorageService` との整合性が高い。
- `StorageService::new` に `http://127.0.0.1:<mapped-port>/storage/v1` を明示的に指定。
  - 理由: 生成クライアント既定値は本番 URL のため、e2e では emulator base URL の差し替えが必須。
- オブジェクトライフサイクルは今回スコープ外にし、バケット系シナリオを強化。
  - 理由: `generated/storage` の `objects_insert` と手動 media upload（`uploadType=media`）の双方が fake-gcs-server (`latest`) で 404 を返し、現行 API 組み合わせでは安定した object 作成ができなかったため。
