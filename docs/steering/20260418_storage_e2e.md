# Steering: Cloud Storage e2e テスト実装

## 目的・背景
Firestore に続いて、エミュレーター上で実行可能な Cloud Storage の e2e テストを追加し、生成クライアントの実運用に近い疎通を継続的に確認できる状態にする。特に `generated/storage` の主要 CRUD 操作を fake-gcs-server で検証し、回帰を早期に検知する。

## ゴール
- `e2e/storage` パッケージを新規追加し、`moon test e2e/storage --target native` で実行可能にする。
- fake-gcs-server で安定実行可能な Cloud Storage API を少なくとも 2 シナリオで検証する。
- Firestore e2e に影響を与えず、既存テスト運用と同じ testcontainers パターンを踏襲する。

## アプローチ
- `e2e/firestore/e2e_test.mbt` を参照し、`NoAuthHttpClient` と `start_emulator()` パターンを Storage 向けに適用する。
- エミュレーターは `fsouza/fake-gcs-server:latest` を使用し、`/storage/v1/b` の HTTP ヘルスチェックで起動待ちする。
- `StorageService::new(client, base_url~)` にエミュレーター URL を渡し、まず `buckets_*` API を中心に検証する。

## スコープ
- 含む:
  - `e2e/storage/moon.pkg` の新規作成（native 対象）
  - `e2e/storage/e2e_test.mbt` の新規作成
  - 完了ドキュメント作成
- 含まない:
  - `generated/` 配下コードの直接修正
  - media download など codegen 未対応 API 形状への対応
  - Firestore e2e の挙動変更
